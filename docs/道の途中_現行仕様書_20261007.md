# 2. アプリ全体の目的

「道の途中。」は、最短・最速で目的地へ到達するためだけのナビアプリではなく、「走り出す理由をひとつ作る」ためのツーリング／ドライブ支援アプリとする。

- 行き先を偶然に任せる。
- 目的地までの途中に道草を足す。
- 短い距離をつないで知らない方向へ進む。
- 登録地点を眺めて自分で行き先を決める。
- 実際に走った場所・思い出を記録する。

# 3. 各メニューの現行仕様

## 3.1 道の駅すごろく

道の駅をマスに見立て、複数地点をつないで「走る理由」を作る遊び。ミッションを付与して各道の駅で小さな目的も作る。

- スタート地点を設定。
- 最大直線距離・目標総走行距離・立ち寄り数を設定。
- 道の駅DBから候補を組み合わせる。
- 任意でミッションを付与。

## 3.2 行先ガチャ

距離と雰囲気を決め、登録地点から目的地を1件ランダム選択する。

- 距離・許容幅を指定する。
- 雰囲気：なんでも／海／山／田舎／市街地／ランドマーク／ライダーズカフェ。
- 「ライダーズカフェ」選択時は、ライダーズカフェDBのみを対象とする。

## 3.3 乗り継ぎガチャ

登録スポット巡りではなく、短い距離を何度もつないで進む「バイク版ジオゲッサー」的な遊び。練習走行・気ままな探索を主目的とする。

- 登録地点DBは目的地生成に使用しない。
- 現在地点から「指定距離＋指定方角」を基にランダム座標を生成する。
- 距離は設定値のおおむね90〜110%で生成する。
- 方角は北／東／南／西を中心におおむね±35°の範囲で揺らす。
- 生成座標は道路へスナップしない。山中・畑等に刺さる場合がある。
- 到達不能な場合は、無理に目的座標へ行かず道路で行ける付近まで進み、そこから次へつなぐ遊び方を許容する。
- 1回ごとの到達地点を次のスタートとして連続ガチャできる。
- 履歴に区間数と直線距離合計を表示する。

> **注記：** 道路スナップは将来要望があれば再検討する。現状は「多少無茶な地点が出ること自体も遊びの味」として採用しない。

## 3.4 寄り道しよう

最終目的地は変えず、スタート→寄り道→目的地という形で小さな道草を追加する。

## 3.4.1 基本ルート

- 1件：スタート → 寄り道1 → 目的地
- 2件：スタート → 寄り道1 → 寄り道2 → 目的地
- 3件：スタート → 寄り道1 → 寄り道2 → 寄り道3 → 目的地

寄り道数は1件／2件／3件。現時点では3件を上限とし、要望があれば拡張する。

## 3.4.2 並び順

複数の寄り道候補を選ぶ場合、スタートから目的地へ向かう進行方向に沿って自動整列する。候補が複数あっても「スタートに近い候補 → その先の候補 → 目的地」の順になるよう処理する。お気に入りルートに既存途中地点がある場合も、既存地点と新規寄り道を進行順で混在させる。

## 3.4.3 道草ジャンル

- おまかせ
- 景色
- 甘いもの
- カフェ
- ごはん
- 温泉
- 道の駅
- 神社・寺
- 公園
- ちょっと変なもの
- 季節
- ライダーズカフェ

## 3.4.4 アプリ登録候補の表示ルール

- 指定した基準地点（スタート地点／目的地）から、設定半径以内にある登録地点を対象とする。
- 特定ジャンル選択時：指定半径内にある、そのジャンルの登録地点をすべて表示する。
- 「おまかせ」選択時：指定半径内にある全ジャンルの登録地点をすべて表示する。
- 全国の登録地点を無条件に全件表示してはいけない。距離条件は必ず効かせる。
- 一覧はアイコン＋名称を中心とした簡潔表示。タップで詳細を開く。
- 詳細から「この登録候補に寄って走る」を実行できる。

## 3.5 ここからどこ行く？

「今いる場所から、このくらい先に何があるか」を距離帯で探す。

- 対象区分：すべて／道の駅／定番スポット／寄り道スポット／ライダーズカフェ。
- ライダーズカフェ選択時はライダーズカフェDBのみを対象とする。
- 現行距離条件は指定距離±10km。

## 3.6 今日の走り方

距離・気分・方角から、その日に合う行き先を探す。

- 大項目：おまかせ／道の駅へ／いいとこ行きたい／ちょっと寄りたい／景色が見たい／なんか食べたい／癒されたい／ライダーズカフェ。
- ライダーズカフェは「なんか食べたい」の小分類ではなく、大項目として独立させる。
- ライダーズカフェ選択時はライダーズカフェDBだけを対象に、距離帯・方角条件で候補を選ぶ。
- 対応する大項目では「探すものジャンルを変える」で細分類を変更できる。

## 3.7 季節を走る

春夏秋冬、その時期らしい景色・場所を目的として走る。季節は手動または現在時期から自動選択。

## 3.8 気になる場所

都道府県・スポット区分・カテゴリから、登録地点を自分で眺めて選ぶ。

- スポット区分：なんでも／道の駅／定番スポット／寄り道スポット／ライダーズカフェ。
- ライダーズカフェ選択時はその都道府県のライダーズカフェDBを表示する。
- カードから詳細、Google Maps、保存、訪問済み、メモへ進める。

## 3.9 登録スポットを見る

登録済みスポットを都道府県・区分・カテゴリ・名称で検索する一覧機能。

## 3.10 旅の履歴

訪問地点、訪問回数、日時、メモ等を記録する。登録地点が近傍にあれば紐付け、なければ座標地点として記録できる。

## 3.11 お気に入りのルート

各メニューで作成・保存したルートを後から再利用する。Google Mapsや車両別ルートを開く。

# 4. ライダーズカフェDB仕様

## 4.1 目的

ライダーが立ち寄れるカフェ・飲食店を、単なる施設一覧ではなく「走る目的」「店とのつながり」「将来の訪問企画」の起点として登録する。

## 4.2 基本項目

| 分類 | 項目 |
| --- | --- |
| 識別・公開 | id / testOnly / publish / gacha / permission |
| 所在地 | 都道府県 / 市区町村 / 店名 / 住所 / 緯度 / 経度 / ナビ検索名 |
| 連絡・公式 | 電話 / 公式Web / Instagram / Facebook 等 |
| 飲食 | foodTypes / signatureMenu / budget |
| 営業 | 曜日別営業時間 / 通常定休日 / 不定休フラグ / 臨時休業情報 |
| 駐車 | 駐車場有無 / 台数 / バイク可 / 大型可 / 路面 / 屋根 |
| 設備 | ヘルメット置場 / ライダー向け設備 |
| 情報管理 | 情報ソース / sourceStatus / lastChecked / notes |
| 掲載許諾 | 未連絡 / 連絡済 / 承認 / 条件付き / 掲載停止 等 |

## 4.3 掲載許諾

- 店舗へ許諾を得る前はDEV動作確認用としてのみ登録し、本番公開しない。
- 未許諾データは testOnly=true / publish=false を基本とする。
- DEVでは掲載許諾状態を表示してもよい。本番ユーザー向けには原則として許諾内部状態を見せない方向で調整する。
- 本番公開前に店名・住所・営業時間・定休日・設備・公式リンクを再確認する。

## 4.4 営業状態の自動表示

曜日別営業時間と現在日時から、原則として以下を自動判定する。

- 🟢 営業中
- 🟡 営業前
- 🔴 本日の営業終了
- ⚫ 本日定休日

将来または手動入力で、🟣 臨時休業／長期休業／⛔ 閉店／不明等を上位状態として扱える設計とする。

## 4.5 通常定休日と臨時休業・不定休

通常定休日と、不定期に設定される臨時休業・店休日は分離して扱う。

- 通常定休日はDBに曜日として登録し、自動判定に使用する。
- 不定期休業の可能性がある店舗は irregularHoliday=true とする。
- 一覧カードには「※ 臨時休業・不定休あり。最新情報は公式Instagram等をご確認ください。」を表示する。
- 詳細画面にも「⚠️ 臨時休業・不定休」を明示する。
- 公式Instagram／公式Web／Facebook等へのリンクを詳細画面に表示する。
- 把握できた特定期間休業（例：9/22〜9/25）は、将来的に臨時休業期間としてDBへ登録し、通常営業時間より優先表示できる設計にする。

## 4.6 休業状態の優先順位（方針）

表示状態の優先順位は、閉店 → 長期休業 → 臨時休業期間 → 通常定休日 → 営業前／営業中／営業終了 を基本とする。

# 7. UI・説明書

## 7.1 使い方モーダル

各メニューは折りたたみ表示とし、展開時に「このメニューの趣旨」→「使い方」の順で表示する。単なる操作説明ではなく、その機能で何を楽しむのかを先に伝える。

## 7.2 共通説明

- スタート地点は現在地・駅・Google Mapsで選んだ場所等から設定できる。
- 距離は候補抽出用の直線距離が中心。実走距離は道路・地形により異なる。
- 実際の通行可否・交通規制・施設営業状況はGoogle Maps、現地標識、公式店舗情報を優先する。

# 8. ナビ・車種に関する基本方針

ナビ用ルートは車種ごとの特性を意識するが、外部ナビの結果を絶対保証しない。125cc以下では高速道路・有料道路回避等を参考設定として使い、最終的には現地標識と交通規制を優先する。

# 9. 今後の検討事項

- ライダーズカフェDBの店舗追加と掲載許諾取得フローの確立。
- 特定期間の臨時休業（開始日〜終了日）をDBで持つ正式スキーマ。
- 本番公開時、掲載許諾状態など管理用情報を一般ユーザー画面から非表示化。
- 「気になる場所」のライダーズカフェ選択時、カテゴリを食事ジャンル等へ切り替えるか検討。
- 寄り道件数は現行1〜3件。四国八十八ヶ所等の多数地点巡回要望が出た場合は、寄り道機能を無理に拡張せず「巡礼／周遊モード」の別機能化を検討。
- 乗り継ぎガチャの道路スナップは現状採用しない。要望が出た場合のみ再検討。

# 10. 本番昇格前チェック

- DEVで実機確認済みか。
